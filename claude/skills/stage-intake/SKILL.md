---
name: stage-intake
description: Stage instructions for `ready`. Preloaded into the intake agent; not invoked directly.
---

Check that the story is buildable before anyone spends tokens on it, and open its channel to the human. You do not improve the story; you accept it or send questions back. Every tool call is a turn and your turns are few: read the files first, then do each git step as one command (`git add … && git commit … && git push …`), and write the log entry and the frontmatter changes in one edit each.

0. The story arrives as the human promoted it from `drafts/`: usually without frontmatter. Its id is the file stem without the slug (`F0001-S0003`), its feature the folder two levels up, whose `FEATURE.md` you read as well.
1. You are on `main`. Create the ticket branch and move there: `git checkout -b ticket/<file stem>`. Everything you commit goes to this branch; `main` stays untouched. If the task names an existing branch instead, you asked before and the human's answer is the last log entry there: stay on that branch, claim (step 2, the frontmatter exists), skip step 3 (the pull request exists), and check the story again from step 4 with the answer. When the answer changes the story (adds or rewords a criterion, an Interface line, a Demo expectation), write exactly that into the story and say in your log entry which log entry it comes from (a new criterion goes before the two closing ones, R5); that is the human's edit carried in, not an improvement of yours. If the meaning of the task changed, rewrite `## Assignment` and its "as of" heading.
2. Claim the story (R6). Write the full frontmatter if there is none: `stage: ready`, `pr: null`, `blocked: null`, `comments_seen: 0`, `claimed_at: <now>`, `round: 0`, `attempts: 0` — these seven and nothing else. Commit and push the branch: `git push -u origin ticket/<stem>`. GitHub cannot open a pull request for a branch it has not seen.
3. Open the draft pull request so the human can follow from the first minute: `gh pr create --draft --head ticket/<stem> --title "<id>: <H1 title>" --body-file -` with the story's `## Assignment` and `## Acceptance criteria` as the body. Put the number it returns into the frontmatter as `pr: <n>`.
4. Check the story's place: the stem looks like `F0001-S0003-slug` with the feature's number, and `FEATURE.md` exists one level up; otherwise that is a question (step 6). Then check the story against `factory/TICKET.md`: every section present, `## Interface` names concrete modules and signatures, every acceptance criterion is testable by one test function without further decisions, `## Demo` has runnable commands with an `Expect:` line each. Every behaviour stated in an `## Interface` comment (a conversion, a format, an ordering, a default) has a criterion that tests it; one without is a question, because two coders will read it two ways and both will pass the tests. Every rule the Interface states — a limit, a validation, an error raised, a default, a rejected input — has a criterion for the side that fails as well as for the side that passes ("a blank title is rejected with `InvalidTitle`", not only "a title is stored"); a rule whose failing side has no criterion is a question, because nobody will test it otherwise and a later story will discover it in production.
5. Check it against the architecture `CLAUDE.md` describes (and the documents it names): the interface puts things where they belong. Check it against `FEATURE.md`: the story is within the feature's scope and not in its "Out of scope".
6. If anything is missing or ambiguous: write the questions as one numbered log entry, set `blocked: question`, clear the claim, commit, push (`git push -u origin ticket/<stem>`), stop. Do not answer them yourself.
7. If the story is complete: append a log entry "intake: accepted" with one indented line per check of steps 4 and 5 and what you found: the sections; the Interface; the criteria (each testable, each rule with its failing side, the two closing ones last); every Demo command with its `Expect:` line, quoted; the architecture; the scope. A check you cannot write a line for is one you did not do: do it. Set `stage: tests`, clear the claim, commit with subject `ticket <id>: ready → tests`, push with `git push -u origin ticket/<stem>`.
